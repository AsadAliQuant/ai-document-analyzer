-----------------------------
Location: main_window.py, lines ~1627-1636

Language Support: Arabic & English

SYSTEM PROMPT (ARABIC):
"أنت مساعد ذكاء اصطناعي يقوم بتحليل مستند واحد مُقدَّم (نص عادي أو ملف PDF أو غيره) ويجيب فقط عن الأسئلة المتعلقة بمحتواه. "
"تعامل مع جميع أنواع الأسئلة مثل: هل فيه أي عنف في المستند؟، كم مرة انذكرت كلمة "___"؟، عن إيش يتكلم الحوار بين "الشخصية" و"الشخصية"؟، هل فيه كلام مسيء للقانون أو للوطن؟، هل فيه استهداف لقبيلة بكلام مباشر أو غير مباشر؟. "

SYSTEM PROMPT (ENGLISH):

"Handle all types of questions such as: \"Does the document include any form of violence?\", \"How many times was the word repeated?\", \"What is the conversation about between character A and character B?\", \"Does the document include offensive ideas or words against the law or the country?\", and \"Does it contain words targeting a tribe?\" "

- Defines AI assistant role for Q&A chat interface
- Constrains AI to only answer from document content
- Supports specialized analysis queries (violence detection, word counts, dialogue analysis)
- Critical for content moderation and compliance use cases
- Enables conversation memory across multiple questions
- Works with RAG system for large document retrieval

USE CASE / ARCHITECTURAL PURPOSE:

- Includes conversation history for multi-turn dialogue
- Context passages are semantically retrieved using vector similarity
- Enables follow-up questions referencing previous answers
- Critical for natural conversational flow in Q&A
- Prevents AI hallucination by grounding in document text
- Conversation history format: "User: question\nAssistant: answer\n..."

SECTION 3: PROMPT ARCHITECTURE & DESIGN PRINCIPLES
================================================================================

3.1 WHY SEPARATE SYSTEM AND USER PROMPTS?
------------------------------------------
- Ollama: Single combined prompt (system + user concatenated)
- Gemini: Separate system_instruction and user message
- Reason: Different API architectures
- Benefit: System prompt sets persistent behavior, user prompt changes per query
- Pattern: Industry standard for conversational AI

3.2 WHY JSON-STRUCTURED SUMMARIES?
-----------------------------------
- Enables programmatic parsing of summary components
- Consistent format across all document types
- Allows UI to display sections separately (key points, methods, conclusions)
- Facilitates future features (search within summaries, comparison, etc.)
- Prevents free-form text variability

3.3 WHY RAG (RETRIEVAL AUGMENTED GENERATION) FOR Q&A?
------------------------------------------------------
- Large documents exceed model context limits (8K-32K tokens)
- Vector similarity search retrieves only relevant chunks
- Reduces hallucination by grounding answers in document text
- Faster inference with smaller context windows
- Enables accurate answers from 500+ page documents
- Uses FAISS/Qdrant for efficient vector storage

3.4 WHY CONVERSATION HISTORY IN PROMPTS?
-----------------------------------------
- Enables natural multi-turn dialogue
- AI can reference previous questions and answers
- User can ask follow-up questions ("what about the second one?")
- Maintains context across entire Q&A session
- Cleared when user presses "Clear" button
- Prevents context confusion from unrelated sessions

3.5 WHY BILINGUAL (ARABIC & ENGLISH)?
--------------------------------------
- Application targets Arabic-speaking users
- Arabic prompts produce better Arabic responses
- English prompts for international users
- Language detection based on UI setting (_current_lang)
- Ensures culturally appropriate responses
- Critical for academic/legal documents in Arabic

SECTION 4: PROMPT MODIFICATION GUIDELINES
================================================================================

4.1 WHEN MODIFYING SUMMARIZATION PROMPTS:
------------------------------------------
✓ DO: Keep JSON structure requirement
✓ DO: Maintain language consistency (Arabic prompts → Arabic output)
✓ DO: Update both Ollama and Gemini versions identically
✓ DO: Test with various document types (PDF, DOCX, images)
✗ DON'T: Remove JSON format specification
✗ DON'T: Add external knowledge requests
✗ DON'T: Change key_points/methods/conclusions structure

4.2 WHEN MODIFYING Q&A PROMPTS:
--------------------------------
✓ DO: Keep "document-only" constraint
✓ DO: Update both system and user prompts consistently
✓ DO: Maintain conversation history mechanism
✓ DO: Test with multi-turn conversations
✓ DO: Update both Ollama and Gemini versions
✗ DON'T: Remove conversation history section
✗ DON'T: Allow external knowledge or web search
✗ DON'T: Break the "Context passages" → "Question" → "Answer" flow

4.3 TESTING CHECKLIST AFTER PROMPT CHANGES:
--------------------------------------------
□ Test with small text document (< 5 pages)
□ Test with large document (> 100 pages, uses RAG)
□ Test with image file (OCR + summarization)
□ Test Q&A with single question
□ Test Q&A with follow-up questions (conversation memory)
□ Test in both Arabic and English UI modes
□ Verify JSON parsing doesn't break
□ Check summary display formatting in UI
