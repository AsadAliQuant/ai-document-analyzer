# Phase 4 - Milestone 2 - Centralize and Secure Gemini API Key Management (Admin-Only)

## Execution rules

- Start only after Milestone 1 acceptance. That provides one stable Gemini-only feature surface to migrate.
- This tracker spans the desktop app, backend API, and existing admin console. Backend/admin tasks must be completed in their owning repositories even though this tracker is stored with the desktop project.
- The raw Gemini key must remain server-side. The desktop must never fetch, receive, log, cache, or bundle it. “Fetch and inject” means the **backend** resolves the active admin-managed key and injects it into server-to-Gemini requests.
- Existing user login/license authentication remains in place for access control. What is removed is per-user Gemini-key entry/storage and any Gemini authentication tied to a desktop user setting or session value.
- Do not remove the desktop key field or local fallback until the server gateway is working and the desktop has migrated to it; this prevents a broken intermediate release.
- A completed task is reopened only for a confirmed regression. Key rotation, migration, and final security checks are distinct downstream tasks.
